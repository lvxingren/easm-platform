白名单是「暴露面基线」：扫描到的开放端口若命中白名单则视为合规、不告警；未命中的才登记为告警并推送飞书。

一、字段格式
字段支持写法示例
IP 规则单个 IP / CIDR 网段 / *（全部 IP）1.2.3.4　10.0.0.0/16　*
端口单端口 / 范围 / 逗号分隔 / *（全部端口）443　1000-2000　22,80,443　*
协议tcp / udp / *tcp　*

注意：白名单 IP 规则不支持 a-b 范围写法（范围仅用于资产台账）；需要连续网段请用 CIDR。

二、批量导入格式

2.1 文本行

每行一条；IP 与端口之间可用空格、逗号或冒号分隔，多端口用逗号；行尾可写 tcp/udp 指定协议（默认 tcp）。

1.2.3.4 22,80,443
10.0.0.5:3306
10.0.0.0/24 1000-2000 udp
* 443

2.2 Excel / CSV 模板

模板固定四列 IP/网段、端口、服务、备注，一行一条规则；首行为表头，系统按列名自动识别。需要区分 UDP 或补充维护信息时，可自行加表头列 协议（tcp/udp/*）、负责人、业务。删掉表头则按模板列序（IP、端口、服务、备注）解析。

列名必填写法示例
IP/网段是单 IP / CIDR / *，也可写成 IP:端口1.2.3.4　10.0.0.0/24
端口否单端口 / 范围 / 逗号分隔 / *；留空且勾选「自动匹配已识别端口」则取该 IP 历史开放端口22,80,443　1000-2000
服务否服务名备注，不参与匹配MySQL
备注否放行依据、工单号等；导入后可在列表行内直接编辑工单 #1024

解析逐行容错：非法 IP/端口、非法协议或端口留空（未勾选自动匹配）的行会被跳过，并回显逐条原因；同一批里 IP+端口+协议 完全相同的规则只算一条，与库中已有规则完全相同的条目会被标记为「已在白名单」，因此线下维护的整表可反复导入而不会产生重复规则。未填备注的条目可用「批量备注」兜底写入。

2.3 导入流程：先预览、再确认

页面导入固定两步：点「解析预览」只解析不写库，得到可逐条勾选的候选清单（含自动匹配已展开的具体端口、批内去重结果与跳过原因）；取消勾选即可剔除，确认无误后点「确认导入」写库。预览阶段就已存在的规则默认不勾选，即使误勾选，写入时仍会再次去重。因此一份整表可安全地多次提交，也只写入新增部分。
脚本对接可直接 POST /api/whitelist/import（一步式写入，去重与容错规则相同）；预览与确认接口分别为 /api/whitelist/import/preview 与 /api/whitelist/import/apply。

三、匹配与告警逻辑

1. 扫描完成后，逐个开放端口与白名单比对，命中任意一条即放行；
2. 未命中的端口 = 违规，进入告警去重（同一 IP+端口+协议在「重告警周期」内不重复告警，仅更新最近发现时间）；
3. 台账范围内的资产默认告警；范围外是否告警由「系统设置 · 范围外发现也告警」控制；
4. 新告警推送飞书，并可在「告警」页标记处理。

四、最佳实践

· 首次使用：先跑一次全端口扫描，再在「扫描记录」页点「生成白名单基线」，把现有暴露面一次性入白，之后只关注新增端口；
· 按业务分组维护白名单，填写「负责人 / 备注」便于追溯；Excel 模板天然带备注列，建议直接在线下维护后整表导入；
· 定期复核白名单，避免把风险端口长期放行。
