# 容量预检自动拆分降级功能

## 功能概述

当容量预检失败（预估耗时超过任务超时）时，平台可以自动将任务按目标数量拆分为多个子批次，并串行执行，而不是直接拒绝任务。

## 使用场景

**典型场景**：471 个目标 × 65535 端口，预估耗时远超任务超时时间
- **传统方式**：直接拒绝，用户需手动调整目标数量或端口范围
- **自动拆分**：将 471 个目标按配置拆分为多个批次（如每批 50 个），依次执行

## 配置说明

### 系统设置页面

在 **系统设置** → **容量预检自动拆分降级** 部分：

1. **启用自动拆分降级**（默认：启用）
   - 勾选后，当容量预检因超时失败时，自动触发拆分
   - 仅对超时类错误生效，其他错误（如 FD 不足）仍直接拒绝

2. **每批目标数量**（默认：50）
   - 控制每个子任务包含的目标数量
   - 较小的值：更细粒度，子任务数更多
   - 较大的值：更粗粒度，子任务数更少

### 配置示例

```
启用自动拆分降级: ✓
每批目标数量: 50
```

对于 471 个目标的任务：
- 自动拆分为 10 个子任务（9 个 50 目标 + 1 个 21 目标）
- 串行执行，每个子任务独立计时、独立状态

## 执行流程

### 1. 任务启动

```
用户创建任务（471 个目标）
  ↓
容量预检失败（预估耗时 8h，超时 1h）
  ↓
检查自动拆分配置（已启用 ✓）
  ↓
计算拆分批次（471 / 50 = 10 个子任务）
  ↓
创建主扫描记录（is_split_task=1, split_total=10）
  ↓
创建 10 个子任务记录（status=pending）
```

### 2. 串行执行

```
子任务 1/10 开始执行（50 个目标）
  ↓
容量预检（子任务规模，通过 ✓）
  ↓
执行扫描（独立计时）
  ↓
完成后触发告警（独立告警）
  ↓
更新主任务进度（split_completed=1）
  ↓
子任务 2/10 开始执行
  ↓
...（重复直到所有子任务完成）
```

### 3. 结果聚合

- **子任务结果**：每个子任务创建独立的扫描记录，结果自然聚合到各个子扫描中
- **主任务汇总**：所有子任务完成后，发送飞书汇总通知
- **告警控制**：每个子任务完成后独立触发告警，主任务不重复生成告警

## 技术实现

### 数据库变更

**新增表**：`scan_sub_tasks`
```sql
CREATE TABLE IF NOT EXISTS scan_sub_tasks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_scan_id INTEGER NOT NULL,
  sub_index INTEGER NOT NULL,
  status TEXT NOT NULL, -- pending | running | done | failed
  specs_json TEXT NOT NULL,
  started_at DATETIME,
  finished_at DATETIME,
  open_ports INTEGER DEFAULT 0,
  error TEXT,
  FOREIGN KEY (parent_scan_id) REFERENCES scans(id)
);
```

**scans 表新增字段**：
```sql
ALTER TABLE scans ADD COLUMN is_split_task BOOLEAN DEFAULT 0;
ALTER TABLE scans ADD COLUMN split_total INTEGER DEFAULT 0;
ALTER TABLE scans ADD COLUMN split_completed INTEGER DEFAULT 0;
```

### 核心函数

1. **CalculateSplitBatches**
   ```go
   func CalculateSplitBatches(specs []store.TargetSpec, batchSize int) [][]store.TargetSpec
   ```
   将目标规格列表按 batchSize 拆分为多个批次

2. **IsTimeoutError**
   ```go
   func IsTimeoutError(err error) bool
   ```
   判断容量预检错误是否因预估耗时超过任务超时

3. **EncodeSpecsJSON**
   ```go
   func EncodeSpecsJSON(specs []store.TargetSpec) string
   ```
   将目标规格列表编码为 JSON 字符串

## 注意事项

### 1. 触发条件

自动拆分仅在以下条件**全部满足**时触发：
- ✓ 启用自动拆分降级配置
- ✓ 容量预检失败原因是**超时**（非 FD 不足等其他错误）
- ✓ 目标数量 **>** 每批目标数量

### 2. 资源占用

- **串行执行**：子任务串行执行，避免资源竞争
- **独立计时**：每个子任务独立计时，不受主任务超时限制
- **累计耗时**：总耗时 ≈ 各子任务耗时之和

### 3. 告警控制

- **子任务告警**：每个子任务完成后独立触发告警
- **主任务汇总**：主任务只发送飞书汇总通知，不重复生成告警
- **白名单比对**：每个子任务独立执行白名单比对

### 4. 失败处理

- **子任务失败**：单个子任务失败不影响其他子任务继续执行
- **部分完成**：主任务状态标记为 `partial`，汇总已完成的子任务结果
- **用户终止**：用户可随时终止主任务，剩余子任务不再执行

## 最佳实践

### 1. 配置建议

**小规模任务**（< 100 目标）：
- 每批目标数量：20-50
- 子任务数：2-5

**中等规模任务**（100-500 目标）：
- 每批目标数量：50-100
- 子任务数：5-10

**大规模任务**（> 500 目标）：
- 每批目标数量：100-200
- 子任务数：视情况而定

### 2. 超时设置

- **主任务超时**：建议设置为单批预估耗时的 1.5-2 倍
- **子任务超时**：继承主任务超时设置，独立计时

### 3. 监控建议

- 关注子任务进度面板，及时发现失败任务
- 查看日志了解各子任务执行情况
- 监控飞书汇总通知确认任务完成

## 故障排查

### 1. 任务未自动拆分

**可能原因**：
- 自动拆分降级未启用
- 容量预检失败原因不是超时
- 目标数量少于每批目标数量

**排查方法**：
```bash
# 查看日志
tail -f data/easm.log | grep "自动拆分"
```

### 2. 子任务执行失败

**可能原因**：
- 子任务容量预检失败
- 网络问题导致扫描超时
- naabu 进程异常退出

**排查方法**：
- 查看任务详情页的错误信息
- 检查子任务的扫描日志
- 确认 naabu 版本和权限

### 3. 进度不更新

**可能原因**：
- 浏览器缓存
- 后端 API 异常

**排查方法**：
```bash
# 手动测试 API
curl http://localhost:8080/api/scans/{id}/subtasks
```
